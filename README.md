## 2026-10-22 继续修复：闪卡复习与来源关联

- 修复评分请求失败但页面仍推进的问题：收到后端成功确认才切换下一张。提交中锁定按钮；请求携带 `expected_reviews` 版本，双击、并发提交或旧请求重放不会重复计次，冲突时需刷新队列。
- 出题按请求数量限制为每次 1～20 张；校验模型输出类型、长度和空内容，并在同一资料版本内规范问题空白/大小写后去重。只使用原文前 9000 字符以内的节选，模型题目和答案仍需人工核对，生成可能产生费用。
- 模型请求期间不占用资料写锁，结果保存前重新核对资料归属及内容版本；出题期间资料被更新、删除或进入等待恢复状态时，不保存过期结果。
- 新卡记录生成时的资料版本。来源更新或删除后，旧卡暂停出现在到期队列，保留题目、答案和学习统计，不自动清理。更新后的资料可以重新生成新版本卡片；已存在的旧卡仍可在管理列表中查看或手动删除。
- 旧卡自动补充空版本字段，**不会猜测或伪造旧来源版本**。旧卡若原资料仍在，会提示“版本未记录”，仍允许复习；无法自动判断它此前是否已经过期，请先核对原文。
- 新增按资料筛选复习、原文打开、来源状态及下次到期时间。复习开始前重新获取队列；加载、生成和删除失败有明确提示，本轮进度只统计成功确认的提交。
- 将原“正确率”如实标为“非错率（含模糊）”：历史统计只记录答错次数，无法还原过去每次模糊评分，故不重写历史或把它冒充严格正确率。掌握数量和到期队列排除已确认来源失效的卡片；总体复习次数仍保留其历史。

复习间隔仍遵循已有设置；若第 0 级间隔为 0 天，答错/模糊后可能立即再次到期，这不是重复保存。离开页面或网络中断后，以重新加载的服务端记录为准，不会自动重发评分。

本轮启动时只做保留式数据库迁移（新增 `flashcards.source_hash`），不重新生成题目或向量、不删除实际学习记录。建议升级前下载完整备份；新版备份与恢复会保留卡片版本及复习进度。

自定义客户端需更新评分接口：`POST /api/flashcards/{id}/answer` 现在需要 `{"result":"correct|fuzzy|wrong","expected_reviews":当前卡片的reviews}`；版本冲突返回 409，不能把失败响应当作成功推进。`GET /api/flashcards/due` 可额外传 `doc_id`，返回卡片新增来源状态与 `next_due` 字段。内置页面已适配。

新增闪卡生成与评分回归、旧库迁移和备份恢复测试，以及 `tests/browser_cards.py` 临时资料的真实浏览器验证。测试使用模拟 AI，不调用你的在线模型，也不操作实际卡片。

## 2026-10-22 稳定性收尾

本轮作为阶段收尾，不再扩展大型功能，重点保护设置、密钥和后台进程。

- 修复设置接口遗漏离线模式及复习参数的问题；保存后刷新不会再回到界面默认值。配置加载失败时禁用保存，并提供重新加载按钮。
- 配置保存前校验 URL、模式、数值范围、复习间隔和切块参数组合；允许本机 `http://127.0.0.1:11434/v1` 等接口，但不允许地址包含账号密码、查询参数或片段。
- 设置使用同目录临时文件、同步落盘及原子替换，本机 Linux 保存权限为 `0600`；失败时保留原文件，空密钥保持不变，界面保存成功后清空已输入密钥。读取配置只返回密钥是否设置，不再返回前后缀。
- 旧版保存的数字字符串会规范为整数；损坏的配置文件不会被静默覆盖。启动配置有无效值时使用有效值/默认值并强制离线，显示警告，避免意外用默认云端地址发请求。修复配置后再明确启用在线模式。
- 「测试连接」只使用当前草稿，不保存设置；草稿为离线模式时不请求供应商。错误提示不回显底层连接异常。测试本身仍可能产生供应商费用。
- 恢复预览兼容旧版数字字符串配置，同时拒绝语义无效的配置；等待恢复期间禁止保存新设置。跨站 `Origin` 的写请求统一拒绝，但这不是身份认证机制。
- 新增轻量 `/api/health`，只检查本机数据库可用性，不扫描资料目录、不调用 AI、不返回密钥和数据路径。`ok` 不代表在线模型或供应商可用。
- Linux 后台控制器核对 PID、进程启动时间、命令及目录，通过绑定进程的 pidfd 发送正常退出信号；兼容本机未编入 pidfd 包装的便携 Python。不支持安全机制时拒绝停止，不退回只按 PID 操作，也不会强杀进程或抢占其他服务端口。

### 本机启动与停止（Linux）

在项目目录执行：

```bash
cd /home/lazyease/nebula-memory/backend
.venv/bin/python start_daemon.py
.venv/bin/python service_control.py status
bash stop_daemon.sh
```

启动后访问 `http://127.0.0.1:8787`。新控制器只有健康检查成功后才报告就绪；日志在数据根的 `last-run.log`，PID 记录在同目录 `.pid`。可用 `start_daemon.py --port 8791` 指定其他空闲端口。设置 `NEBULA_MEMORY_HOME` 时，这两份运行记录随数据根存放。

旧版数字 `.pid` 或失效记录不会自动覆盖、删除或用于停止进程。遇到提示时，先人工核对并关闭旧服务，再把旧 `.pid` 移到备份位置；不要直接拿旧数字执行 `kill`。本轮没有擅自处理实际目录里的旧运行记录。已有前台服务也不能由新控制器接管，可继续从原终端正常停止。

也可前台运行（不依赖 PID 记录）：

```bash
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8787
```

- 本轮不修改实际资料或重建索引；新配置与源码需要重启后端、刷新页面后生效。此前旧切块问题仍需手动重建索引才能修复旧资料，使用在线向量服务可能收费。

- 自动测试使用独立临时目录、离线向量和模拟供应商；不会验证你的真实在线密钥、费用或供应商稳定性。桌面安装包未在本轮重新打包，验证对象为本机后端与浏览器版。
- 新增配置/进程控制回归、`tests/browser_settings.py` 设置故障流程，以及 `tests/service_smoke.py` 真实临时后台服务启停验证。

### 恢复方式

1. 在「设置 → 恢复备份」选择 ZIP，检查预览后确认。
2. 确认后当前资料仍保持原样，也可以取消等待恢复；新的导入任务暂停接收。
3. 完全关闭并重新启动知识库后端。启动时应用准备好的备份，原数据完整保留在 `backend/data-before-restore-<编号>/`。
4. 在设置页点击「重建向量索引」，完成后恢复检索。索引重建按当前模型配置执行，使用在线模型时仍会调用所配置的服务。

恢复支持新版备份及包含完整原文的旧版格式 1 备份；压缩包上限 512 MB，解压总量上限 4 GB、最多 10000 个条目。`.env` 不在备份中，需单独保管。预览文件和保留的旧数据目录会额外占用磁盘空间，系统不会自动删除旧数据。

上传每次最多 50 个文件、合计 500 MB，单文件仍为 100 MB。导入记录位于 `backend/data/import-jobs.sqlite3`；恢复资料时不会自动恢复旧任务队列。本文的后台队列针对文档文件上传，网页链接导入仍沿用原流程。

基于 RAG 的个人知识管理助手：导入你的文档，AI 自动整理入库，之后**只基于你自己的资料**回答问题，并标注来源出处。

## 当前功能（v2）

- 📤 文档导入：PDF / Word / TXT / Markdown，自动解析、切块、向量化
- 🏷 AI 自动整理：生成标题 / 分类 / 标签 / 摘要
- 💬 知识问答：RAG 检索 + DeepSeek 回答，答案附带「来源: 文件 第N页」
- 🔍 语义搜索：大白话描述就能找到相关内容，显示匹配度
- 🧷 长期记忆：告诉 AI 你的设备/偏好/背景，问答时自动参考
- 🗂 多知识库：工作、学习、个人资料独立管理，文档、会话与闪卡互不串库
- 💬 多会话：新建、重命名、删除对话，每个会话保留独立上下文
- 🌐 网页导入：粘贴文章链接，自动提取正文并加入当前知识库
- 📖 阅读助手：查看原文并针对当前段落提问
- 🧠 复习闪卡：AI 从文档生成题目，支持间隔复习与掌握度统计
- 🖼 图片 OCR：可选安装 OCR 依赖后导入常见图片格式

## 技术架构

```
Electron 壳(可选) / 浏览器访问
        │
Vue3 + Vite 前端 (frontend/)
        │
FastAPI 后端 (backend/)
├── 解析: PyMuPDF(PDF带页码) / python-docx / 纯文本
├── 向量库: Chroma(本地持久化) + SQLite(元数据)
├── 向量化: 智谱 embedding-3(云端) | mock离线向量(测试)
└── 对话: DeepSeek(OpenAI兼容, 可换任意中转站)
```

上传文件、数据库和向量索引位于本机 `backend/data/`；自动导入的原件也可能位于 `知识库文件夹/<知识库>/已导入/`，新版完整备份会包含这些原文。

设置页提供「下载完整备份」：备份包含数据库、原始资料和应用配置，向量索引可在恢复后重建。
配置中可能保存 API Key，因此备份文件应按密码文件保管。

为避免误把系统文件或内网服务当成知识资料，上传文件限制为 100MB，网页导入会拒绝
localhost、局域网、链路本地地址及跳转到这些地址的链接。

## 快速开始

```bash
# 0. 准备: Python3.11 + Node20 (runtime/ 内已有便携版则跳过)

# 1. 后端依赖
cd backend
python3.11 -m venv .venv
.venv/bin/pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

# 2. 配置密钥
cp .env.example .env   # 编辑: DEEPSEEK_KEY 必填; ZHIPU_KEY 填了才有语义检索质量

# 3. 启动后端(同时服务前端页面)
.venv/bin/python start_daemon.py     # 后台运行, 日志 last-run.log
# 或前台: .venv/bin/python -m uvicorn app.main:app --port 8787

# 4. 构建前端(首次)
cd ../frontend && npm install && npm run build

# 5a. 浏览器使用
打开 http://127.0.0.1:8787

# 5b. 桌面App方式(Electron, 需要桌面环境)
cd ../electron && npm install
../start-desktop.sh
```

## 密钥说明 (.env)

| 变量 | 用途 | 不配会怎样 |
|------|------|-----------|
| `DEEPSEEK_KEY` | 对话+自动摘要 | 功能不可用 |
| `ZHIPU_KEY` | 向量化(open.bigmodel.cn 申请) | 退化为 mock 哈希向量, 仅能联调不能语义搜索 |
| `CHAT_BASE_URL` | OpenAI兼容地址, 可指中转站/ollama | 默认官方 |

### 切换向量模型

不同向量模型输出的维度可能不同。切换 `EMBED_MODEL` 或在线/离线模式后，
如果旧知识库与新模型维度不一致，系统会自动退回关键词检索，不会再导致查询崩溃。
进入「设置」后按提示点击「重建向量索引」，即可用当前模型恢复语义检索。

重建时会先生成临时索引，成功后才替换旧索引；解析或模型调用失败时旧索引仍会保留。

## API 一览

```

POST/GET /api/import/jobs    新建/查看后台文档导入任务
POST /api/import/jobs/{id}/{stop|resume|retry}    停止/继续/重试
GET /api/backup    下载完整备份
POST /api/backup/preview    预览 ZIP 备份
POST /api/backup/restore    确认下次启动恢复
POST /api/backup/restore-cancel    取消等待恢复
GET  /api/docs      文档列表      DELETE /api/docs/{id}
POST /api/search    语义搜索 {query}
POST /api/chat      RAG问答 {question}
GET  /api/history   对话历史
GET/POST/DELETE /api/sessions  对话会话
POST /api/memory    添加长期记忆 {content}   GET/DELETE 同路径
GET/POST/DELETE /api/kbs       多知识库
POST /api/import/links         网页链接导入
GET/POST/DELETE /api/flashcards 闪卡与复习
GET  /api/stats     统计
```

## 升级验证

后端测试：在 `backend/` 执行 `.venv/bin/python -m unittest discover -s tests -v`。测试时应将 `NEBULA_MEMORY_HOME` 指向独立临时目录，设置 `NEBULA_DISABLE_INBOX=1`，以隔离真实资料。

浏览器回归：`backend/tests/browser_upgrade.py` 使用临时知识库与离线测试向量，验证上传、刷新、服务重启续跑、备份预览、恢复、旧数据保留和重新检索；需要 Playwright，可通过 `CHROMIUM_PATH` 指定 Chromium。本轮未调用真实付费模型，也未对现有用户资料执行恢复。
